# PGRE Simulator — Build Spec

## 1. Goal

Import a GRE Physics practice-test PDF (an ETS practice book) once, then sit it in a browser under test-day conditions with automatic scoring.

Two parts:

- **Importer** (`tools/importer.py`): deterministic Python. It turns a PDF into `exams/<id>/exam.json` plus cropped question images. Claude is involved only to fix what the importer flags.
- **Runner** (`runner/`): a static HTML/JS app that delivers and grades any imported exam. It is built once and needs no changes per exam.

Priorities, in order:
1. A correct answer key and correct scoring
2. Faithful question display
3. Test-day realism
4. Minimal Claude token use
5. Polish

## 2. Non-goals

- No transcription of questions or equations to text or LaTeX. Questions are images cropped from the PDF.
- No backend, accounts, database, build step, npm packages or CDN dependencies.
- No grading by Claude, and no AI explanations (see §10).
- Not a general PDF quiz tool. Tune it for ETS physics practice books: the current ~70-question book and the older 100-question books (e.g. GR0877).

ETS content (PDFs, crops) stays local. Don't commit or publish it.

**Page numbers.** All page numbers in reports, overrides and `exam.json` are 1-based PDF page indices, not the book's printed page numbers.

## 4. Data formats

### 4.1 `exams/<id>/exam.json`

```json
{
  "version": 1,
  "id": "gr0877",
  "title": "GR0877",
  "source": "gr0877.pdf",
  "importedAt": "2026-10-20T14:30:00Z",
  "questionCount": 100,
  "timeLimitMin": 170,
  "timeLimitSource": "text",
  "scoring": {
    "raw": "R-W/4",
    "rawSource": "text",
    "rounding": "half-up",
    "scale": [ { "raw": 100, "scaled": 990, "pct": 94 } ]
  },
  "reference": ["img/reference-1.png"],
  "sets": [ { "id": "12-13", "first": 12, "last": 13, "image": "img/set-12-13.png" } ],
  "questions": [
    { "n": 1, "page": 9, "images": ["img/q001.png"], "answer": "C",
      "set": null, "pplus": 72, "category": null }
  ],
  "importFlags": []
}
```

Field notes:

| Field | Meaning |
|---|---|
| `timeLimitSource`, `scoring.rawSource` | `"text"` (read from the book), `"inferred"` or `"override"` |
| `scoring.raw` | `"R"` (number right) or `"R-W/4"` (right minus a quarter of wrong). Blanks are never wrong. |
| `scoring.scale` | One entry per integer raw score, after expanding ranges. `pct` is optional. |
| `questions[].images` | One or more segments. A question that crosses a page break has two. |
| `questions[].set` | The `id` of a shared-stem set, or `null` |
| `pplus`, `category` | Optional. Filled only if the book's answer key prints them. |
| `importFlags` | Flags left unresolved at import, shown in proof mode |

### 4.2 `exams/<id>/overrides.json`

All keys are optional. The importer applies overrides after automatic extraction, and each key replaces only what it names.

```json
{
  "pages": [9, 58],
  "expected": 100,
  "timeLimitMin": 170,
  "scoring": { "raw": "R-W/4" },
  "answers": { "37": "D" },
  "crops": { "37": [ { "page": 21, "bbox": [54, 118, 560, 402] } ] },
  "sets": [ { "first": 12, "last": 13, "page": 8, "bbox": [54, 90, 560, 210] } ],
  "reference": [ { "page": 3, "bbox": [40, 60, 572, 740] } ],
  "scale": [ { "raw": 100, "scaled": 990, "pct": 94 } ],
  "ignoreFlags": ["CHOICES:q58"]
}
```

- `bbox` is `[x0, y0, x1, y1]` in PDF points (PyMuPDF page coordinates).
- `pages` is the first and last page of the exam itself.
- `scale`, if present, replaces the whole table.

### 4.3 `exams/index.json`

```json
[ { "id": "gr0877", "title": "GR0877", "questionCount": 100, "timeLimitMin": 170 } ]
```

The importer regenerates this file on every run by scanning `exams/*/exam.json`.

## 5. Importer

### 5.1 CLI

```
python tools/importer.py PDF [--id ID] [--expected N] [--pages FIRST-LAST] [--debug-page P]
```

| Option | Behavior |
|---|---|
| `--id` | Defaults to the lowercased PDF filename stem. |
| `--expected` | Defaults to the answer key's length. If neither is available, raise a `COUNT` flag. |
| `--pages` | Overrides automatic detection of the exam's page range. |
| `--debug-page P` | Prints page P's words compactly, one line each (`x0 y0 text`, rounded to whole points), then exits. Use this to learn a layout or pick override coordinates without viewing images. |

Exit codes: `0` clean, `1` flags present, `2` fatal. Fatal means the file is unreadable, OCR is needed but unavailable, or zero questions were found.

Requires Python 3.11+, `pymupdf` and `pillow`. `ocrmypdf` (with tesseract) is optional and only needed for scanned PDFs.

### 5.2 Pipeline

1. **Reset.** Delete `img/` and `review/` for this id so every run is idempotent.

2. **Text layer.** If most pages have under ~50 extractable words, run `ocrmypdf --deskew --rotate-pages IN exams/<id>/source-ocr.pdf` and use that file instead. Record `ocr=yes` in the summary.

3. **Exam pages.**
   - The exam starts at the first page where a "1." anchor is followed by sequential anchors.
   - It ends at the page holding the last question, before the answer-key and scoring section.
   - The "TABLE OF INFORMATION" block before question 1 is the reference sheet. Crop it to `img/reference-N.png`.

4. **Content box.** Drop headers and footers: lines in the top or bottom 10% of the page whose text (with digits removed) repeats on at least 40% of exam pages. This catches page numbers, "GO ON TO THE NEXT PAGE", running titles and copyright lines.

5. **Anchors.**
   - A question-number token matches `^(\d{1,3})\.$`, or a number with a period glued to the next word.
   - It must be the first token on its line and within ~15 pt of a column's left edge.
   - **Sequence constraint:** accept a candidate only if its number is exactly the last accepted number + 1. This rejects false positives inside equations.
   - **Columns:** cluster the anchors' x0 values. Two or more clusters with at least 5 members each means a multi-column layout. Reading order is column by column, top to bottom, per page.

6. **Regions.**
   - A question runs from 4 pt above its anchor to 4 pt above the next anchor in the same column, or to the bottom of the content box.
   - **Page breaks:** if a region ends at the content bottom, any content above the next anchor at the top of the next page is a second segment of the same question.
   - **Tightening:** shrink each segment to the union of the text spans, vector drawings and embedded images inside it, plus 6 pt of padding. On OCR'd pages, trim whitespace by scanning pixels instead.

7. **Shared stems.**
   - A stem starts at a line matching `Questions?\s+(\d+)\s*(?:-|–|—|and|through|to)\s*(\d+)` (case-insensitive).
   - That line ends the preceding question's region.
   - The set's region runs from that line to the first anchor of the set. Save it as `img/set-A-B.png` and point each member question's `set` at it.

8. **Choices.** Count the `(A)`–`(E)` tokens in each question's segments. Expect exactly one of each.

9. **Render.**
   - Render each segment at 2.5× zoom (~180 dpi) to PNG.
   - Filenames: `q037.png`; `q037-2.png` for a continuation; `set-12-13.png`; `reference-1.png`.

10. **Answer key.**
    - Find the section after the exam pages containing "answer key", "worksheet" or "correct answer".
    - Group words into rows by y (±2 pt) and parse `number letter [P+ integer] [category]`.
    - Tables are often printed as several column groups side by side, so split each row wherever the pattern repeats.
    - Check: exactly one answer for every question 1..N, and every letter is A–E.

11. **Conversion table.**
    - Find the "score conversion" or "total score" table.
    - Parse each row as raw score or raw range (`85-87` or `85–87`) → scaled score, with an optional percentile.
    - Expand ranges to one entry per integer raw score.
    - Check: scaled scores never decrease as raw increases; each scaled score is between 200 and 990 and a multiple of 10; no raw score appears twice; no gaps.

12. **Scoring rule and time limit.**
    - **Penalty:** if the worksheet or instructions mention subtracting one-fourth, one-quarter, ¼ or W/4 of wrong answers, the rule is `R-W/4`.
    - **Number correct:** if they say the score is the number answered correctly, the rule is `R`.
    - **Neither found:** use `R` and raise a `RULE` flag.
    - **Rounding:** half-up unless the text says otherwise.
    - **Time limit:** read it from text such as "testing time is X" or "N minutes". If none is found, infer 170 minutes for ≥90 questions and 120 minutes otherwise, mark it `"inferred"` and raise a `RULE` flag.

13. **Finish.** Apply `overrides.json`, validate, write `exam.json` with the unresolved flags in `importFlags`, and regenerate `exams/index.json`.

14. **Review overlays.** For each page named in a flag, render the page at 1.2× zoom and draw on it:
    - every crop box, labeled with its question number
    - a ruler along the top and left edges, labeled every 50 pt in PDF points

    Save the result as `review/pNNN.png`.

### 5.3 Report (stdout)

Output is one summary line, then the flags. Keep it to 25 lines or fewer, truncating with `+N more`. Print no other logging.

```
gr0877: q=100/100 key=100/100 scale=0..100 sets=4 ref=1 ocr=no rule=R-W/4(text) time=170(text)
FLAGS (2):
CHOICES q058 p30 found=0 (graphical choices?) -> review/p030.png
HEIGHT  q071 p37 h=812pt (2.6x median) -> review/p037.png
```

Flag codes:

| Code | Raised when |
|---|---|
| `NUM_GAP` | A question number is missing or duplicated |
| `COUNT` | Questions found ≠ expected count |
| `CHOICES` | A question doesn't contain exactly one each of (A)–(E) |
| `HEIGHT` | A segment is taller than 2.2× or shorter than 0.35× the median height |
| `SPLIT` | A question crosses a page break (check the continuation) |
| `SET` | A set's range doesn't match the questions found |
| `KEY` | The answer key is missing, short or has an invalid letter |
| `SCALE` | The conversion table is missing, has gaps, decreases, or has out-of-range values |
| `RULE` | The scoring rule or time limit was inferred, not read from the book |
| `REF` | The Table of Information wasn't found |

- Flags listed in `ignoreFlags` as `CODE:target` (e.g. `CHOICES:q58`) are suppressed.
- `KEY`, `SCALE` and `RULE` flags point to an overlay of the relevant worksheet page.

### 5.4 Tests

Use pytest with synthetic inputs only, so no ETS content goes into the repo.

- `fixtures/make_fixture.py` uses PyMuPDF to generate a 6-question PDF containing:
  - one shared-stem set
  - one question that crosses a page break
  - one equation with a "2." false-positive anchor
  - a header and a footer
  - an answer key
  - a conversion table
- **Unit tests:**
  - anchor sequencing
  - column detection
  - parsing answer-key rows printed in several column groups
  - expanding and validating conversion-table ranges
  - detecting the scoring rule from text
  - merging overrides
- **End-to-end test:** run the importer on the fixture, expect a clean exit, and check `exam.json`.

## 6. Runner

### 6.1 Tech

- Files: `runner/index.html`, `app.js`, `scoring.js`, `style.css`.
- Vanilla JS with ES modules; no libraries.
- Serve from the repo root: `python -m http.server 8000`, then open `http://localhost:8000/runner/`.
- The app loads `../exams/index.json` and `../exams/<id>/exam.json`.
- Charts are inline SVG.

### 6.2 Screens

1. **Home.**
   - Lists exams from `index.json` with question count, time limit, and last and best scaled score.
   - Each exam has Start and Proof buttons.
   - Shows a resume banner when an attempt is in progress.
   - Has buttons to export and import history as a JSON file.

2. **Start.**
   - Shows the title, question count and time limit.
   - Mode: Timed (default) or Untimed.
   - Short directions that state the scoring rule (whether there is a guessing penalty).
   - Begin button.

3. **Question screen**, modeled on the ETS computer-delivered interface:
   - **Top bar:** exam title · "Question i of N" · countdown timer (h:mm:ss) with a Hide/Show Time toggle.
   - **Toolbar:** End Test · Reference · Review · Mark · Back · Next.
   - **Body:**
     - The set stem image (if any), then the question image(s).
     - Images fit the content width (max ~900 px) and are never upscaled past their natural size.
     - Below them, five radio options labeled (A)–(E). These are labels only; the choice content is in the image.
     - A "Clear answer" link.
   - **Keyboard:** A–E select, ←/→ Back/Next, M marks, R opens Review.

4. **Review.**
   - A table of all questions showing number, Answered/Not Answered and the marked flag.
   - Filters for unanswered and marked.
   - Clicking a row jumps to that question. A Return button goes back.

5. **Reference.** An overlay showing the Table of Information image(s). The timer keeps running.

6. **Ending the test.**
   - End Test opens a confirmation dialog showing how many questions are unanswered and marked.
   - A non-blocking banner appears at 5 minutes remaining.
   - When time expires, the test submits automatically and shows a notice.

7. **Results.**
   - **Headline:** scaled score and percentile (if available); raw score with the formula shown (e.g. `62 − 20/4 = 57`); correct, wrong and blank counts; time used.
   - **Category breakdown:** correct/total per category, if the exam has categories.
   - **Question table:** #, your answer, correct answer, ✓/✗/–, time spent, P+ (if present), marked.
     - Filters: wrong, blank, marked, slow (over 2× the median time).
     - Clicking a row shows the question image with the correct choice highlighted, and your choice too if it differs.
   - **Pacing chart:** time per question as bars, with a median line.

8. **Proof mode** (`?proof=<id>`):
   - Every question on one scrolling page: set stems, question images, correct answer letter, page number.
   - Also shows the reference images, the conversion table and any `importFlags`.
   - Purpose: the user spot-checks an import in a minute without spending any tokens.

### 6.3 State

- **In-progress attempt.** Kept in localStorage under `pgre.inprogress.v1` as `{examId, mode, startedAt, deadline, current, answers, marked, timeSpent}`.
  - Saved on every change and every 5 s.
  - A reload resumes the attempt. The timer counts down to `deadline` (epoch ms), so time keeps running while the page is closed, as on test day.
- **Finished attempts.** Appended to `pgre.attempts.v1`. Store the raw answers, not just scores. The results and history screens always recompute scores from the current `exam.json`, so a corrected key fixes old attempts.
- **Time per question.** Accumulates only while the question is on screen and the tab is visible (`visibilitychange`).
- **Storage failures.** Wrap every storage call in try/catch. If storage is unavailable, the app still works for the session and shows a warning.

### 6.4 Scoring (`scoring.js`)

```
R = number correct, W = number wrong (blanks excluded)
raw    = R                 if rule == "R"
raw    = R - W/4           if rule == "R-W/4"
rawInt = round half-up
scaled = scale lookup of rawInt, clamped to the table's min..max
```

Run the tests with `node --test runner/scoring.test.js`. They cover:
- rule `R`
- rule `R-W/4` with rounding cases (57.25→57, 57.5→58, negative raw)
- clamping below the table's minimum
- lookups through expanded ranges
- category tallies

## 7. Claude Code integration

### 7.1 `.claude/skills/import-test/SKILL.md`

```markdown
---
name: import-test
description: Import a GRE Physics practice-test PDF into the exam runner and fix anything the importer flags. Use when asked to import or add a practice test PDF.
---

1. Run `python tools/importer.py <pdf>`. Add `--id <id>` or `--expected N` if the user gave them.
2. Exit 0: reply with the summary line. Done.
3. Exit 2: reply with the error line. Stop.
4. Exit 1: handle each FLAG.
   - Open only the review image named on that flag's line. For exact text coordinates, use `--debug-page <p>` instead of viewing more images.
   - Fix it in `exams/<id>/overrides.json` (create the file if missing): crop boxes in PDF points, answers, set ranges, scoring rule, time limit or scale.
   - If the overlay shows the crop is actually correct (e.g. graphical answer choices), add the flag to `ignoreFlags` instead.
   - Never edit exam.json, never open the source PDF, never view img/ crops in bulk.
5. Rerun the importer. Stop after at most 3 fix-and-rerun cycles.
6. Reply in 5 lines or fewer: the summary line, what you overrode, any flags left, and
   "Spot-check: http://localhost:8000/runner/?proof=<id>".
```

### 7.2 `.claude/settings.json`

These rules let headless imports run without permission prompts. They also deny direct PDF reads, enforcing the token rule.

```json
{
  "permissions": {
    "allow": [
      "Bash(python tools/importer.py:*)",
      "Read(./exams/**)",
      "Edit(./exams/**/overrides.json)"
    ],
    "deny": [
      "Read(./pdfs/**)",
      "Read(./exams/**/source-ocr.pdf)"
    ]
  }
}
```

Check this rule syntax against the current Claude Code permissions docs during M5.

### 7.3 Usage after the build

```
claude -p "Import pdfs/gr0877.pdf using the import-test skill" --model sonnet
```

Each import starts with a fresh context. A clean PDF costs one short tool loop.

## 8. Build plan

Work one milestone at a time. Finish each with its acceptance check, then stop and report to the user.

To learn a PDF's layout during the build, run `--debug-page` on 3–4 representative pages: the first exam page, a page with a figure, the answer key and the conversion table. Don't read whole PDFs or view every page.

| # | Milestone | Acceptance |
|---|---|---|
| M1 | Importer: anchors, regions, sets, crops, key, scale, rule/time, overrides, report, `--debug-page`, fixture + pytest | `pytest tools/` passes. On the user's first real PDF, all questions are found, the key and scale parse, and at most a handful of flags remain. |
| M2 | Runner basics: home, question view, answering, grading, proof mode, `scoring.js` + tests | The user confirms the proof page for the first PDF looks right, and the node tests pass. |
| M3 | Test-day UI: timer with hide/show, mark, review screen, reference overlay, end-test dialog, expiry, resume after reload | A timed run end-to-end. A reload mid-test resumes with the correct remaining time. |
| M4 | Results and history: full results screen, filters, pacing chart, history, export/import, recompute on load | Raw and scaled scores for a sample answer set match a hand calculation from the book's worksheet. |
| M5 | Claude Code wiring: skill, settings.json, headless import | A second PDF imports headlessly through the skill with no help from the user. |

## 9. Definition of done

- Importing a clean PDF takes one command and a few seconds, and ends with a clean report.
- Proof mode shows every question with no clipped stems, figures or choices.
- A timed exam can be sat start to finish and reliably resumes after a reload.
- Scores match the book's worksheet.
- Taking and grading an exam uses zero Claude tokens.

## 10. Later (out of scope for now)

- **Retake mode:** only the wrong or marked questions from a past attempt, untimed.
- **On-demand explanation:** a button sends one question image plus the correct answer to Claude. Each use costs tokens.
- **Topic tags for books without categories:** one cheap Haiku pass over the question images, with results cached in `overrides.json`.
